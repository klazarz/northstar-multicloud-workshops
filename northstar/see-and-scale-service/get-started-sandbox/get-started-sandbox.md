# Get Started

## Introduction

Use the Azure database and access instructions provided with your Run on Multicloud reservation. If you completed the previous workshop, check which database was handed off for this session.

Estimated lab time: 10 minutes after preparation.

### Objectives

* Identify the assigned database, SQL user and sandbox permissions.

### Prerequisites

* Oracle Autonomous AI Database Serverless on Azure running Oracle AI Database 26ai. Confirm the version with your environment owner before running the SQL.

* A reservation providing an available Oracle Autonomous AI Database Serverless instance on Azure, Azure Monitor access, an approved client network path and a dedicated workshop user.
* The inventory dataset or a clean schema with permission and quota to create it.
* The provider's instructions on whether resource allocation changes are allowed and who restores them.

## Task 1: Open your assigned environment

1. Open the reservation instructions and sign in to the assigned Azure environment. Identify the database for this workshop; if you used a fallback in the previous workshop, verify where the sample data is located.
2. Open the supplied Database Actions URL from the approved client or remote desktop and sign in using the assigned workshop credentials. Select **SQL**.
3. Confirm whether the reservation permits a temporary ECPU change, the approved target and restoration procedure. If a change is unavailable, you can complete the decision exercise without applying it.
4. If the database, credentials, metrics access or instructions are missing, contact the facilitator or reservation support. Do not share passwords, wallet files or private connection details in public messages.

The provider must confirm that the Run on Multicloud reservation supports this Azure service and these capabilities. A generic OCI sandbox alone does not establish Azure access.

You may now **proceed to the next lab**.
